# 产品需求文档（PRD）｜StudyFlow 全栈学习管理系统

项目所有者：汤甜甜（课程实训）；版本：V1.0；日期：2026-10-20。

## 一、项目定位与价值

围绕大学生日常课程项目、学习规划与复盘中“目标分散、进度难追踪、学习投入缺少证据”的管理场景，StudyFlow 将项目、任务、学习笔记和专注时长统一为可检索、可统计、可持续保存的个人学习工作台。与浏览器内独立保存的静态效率工具不同，StudyFlow 采用真实后端 REST API、SQLite 关系数据库及用户级访问控制，展示从用户输入到服务器校验、数据库写入，再到看板与数据分析反馈的完整工作闭环。

## 二、目标用户与核心场景

- 学习者：制定本周课程计划、创建项目与任务、追踪进度。
- 项目负责人：按优先级与截止日期分配个人待办，监督计划推进。
- 课程考核老师：验证完整前端、后端、数据库的交互，观察持久化效果与接口测试。

## 三、需求矩阵与验收标准

| 编号 | 功能模块 | 验收点 | 后端/数据证据 |
| --- | --- | --- | --- |
| R01 | 账户体系 | 注册、登录、退出、重新登录 | users/sessions；PBKDF2 加盐摘要 |
| R02 | 首次体验 | 新用户生成演示项目、任务、笔记及专注记录 | SQLite 示例数据与独立用户标识 |
| R03 | 学习仪表盘 | 任务总数、完成率、专注时长、近期待办 | /api/dashboard 聚合查询 |
| R04 | 项目管理 | 创建、编辑、删除项目、完成进度展示 | projects 表；项目级任务统计 |
| R05 | 任务看板 | 新增、修改、三状态切换、优先级、截止日期、删除 | tasks 表；/api/tasks REST CRUD |
| R06 | 任务检索 | 可搜索、按高/中/低优先级筛选 | 前端即时过滤授权后获取的任务 |
| R07 | 学习笔记 | 新建、编辑、保存、删除、刷新后保留 | notes 表；/api/notes REST CRUD |
| R08 | 专注空间 | 15/25/45 分钟计时、暂停、重置、记录 | focus_sessions 表；/api/focus |
| R09 | 数据分析 | 最近 7 日时长、逾期任务、任务状态分布 | SQL 统计与页面渲染 |
| R10 | 数据备份 | 导出自己所有项目、任务、笔记与专注记录 | /api/export 返回 JSON |
| R11 | 数据隔离 | A 账号不能读取、修改、删除 B 账号的数据 | 所有业务 SQL 强制限定 user_id |
| R12 | 交付与部署 | 本地一条命令启动，具备 Docker 配置 | server.py、Dockerfile、README |

## 四、体验流程

游客进入网站 → 注册 → 后端创建用户并初始化示例数据 → 仪表盘显示统计 → 在任务看板新增和编辑任务 → 在专注空间保存一条学习记录 → 切换数据分析观察指标变化 → 刷新浏览器验证持久化 → 导出本人 JSON 数据 → 退出和再次登录。

## 五、质量及约束

响应式兼容 Chrome/Edge 桌面和移动浏览器。所有用户输入在前端渲染时转义，服务器实行字段长度校验和参数化 SQL。默认部署模式为单实例 SQLite；将服务发布至易失文件系统的容器平台时需采用持久卷才能实现可靠长期保存。本系统为课程教学演示项目，正式对公众运营前需加入速率限制、账户恢复与更完整的安全防护。

## 六、验收边界

“完整全栈”以真实 REST API + SQLite 文件为依据，而非 HTML 中使用 localStorage 模拟。课程要求中的“之前已经部署的项目”由仓库原有 TTT-homework 静态项目承担，StudyFlow 保持独立子目录，原项目不迁移、不拆除。
