# 课程最终验收视频｜推荐录制脚本（约 5–7 分钟）

## 录制前准备

先确认 Python 已安装。下载仓库文件后在 `studyflow` 目录双击 `启动StudyFlow.bat`（Windows）或在终端输入 `python server.py`；再用 Chrome/Edge 打开 `http://127.0.0.1:8001/`。建议选用 1920×1080 分辨率、浏览器缩放 90–100%。准备原网站的实际可用链接。

## 第一幕｜说明技术形态（0:00–0:40）

画面显示 StudyFlow 登录页、GitHub 新项目目录中的 `server.py`、`web`、`tests`。讲述：“本次复杂项目选择全栈开发方向。浏览器负责操作界面，Python 提供真实 REST API，SQLite 记录用户、项目、任务、笔记与专注数据。新项目与前几次的静态作品集独立。”

## 第二幕｜完整演示主要业务（0:40–3:10）

1. 点击“立即注册”，创建一个新的演示账号，首次进入即出现示例项目、任务与统计卡片。
2. 打开“任务看板”，展示三状态任务、优先级。新建任务“完成课程项目验收”，设置项目和截止日期，保存后显示在看板，点击移动到“进行中”和“已完成”。
3. 刷新页面（F5）并确认新任务仍在，说明记录来自 SQLite，不是只保存在当前网页。
4. 打开“项目管理”，点击“创建项目”，命名“本周学习计划”；展示项目完成进度统计。
5. 打开“专注空间”，展示番茄钟。为了控制录制时长，使用“记录 25 分钟”补录按钮，立即观察右侧记录和累计时长变化。可现场开始计时 5–10 秒，再暂停。
6. 打开“学习笔记”，修改并保存正文。跳转“数据分析”，查看七日柱状图及任务状态统计。点击顶部“导出数据”，展示生成的 JSON 文件。

## 第三幕｜证明后端、数据库和隔离（3:10–4:15）

展示终端：执行 `python -m unittest discover -s tests -v`，最后出现“Ran 8 tests ... OK”。如有 SQLite 查看器可展示 `data/studyflow.sqlite3` 文件及表 `users`、`tasks` 等。不需要向老师展示注册密码。退出登录，再登录账号确认任务存在。可选用另一个浏览器无痕窗口注册不同账号，说明两套数据相互独立。

## 第四幕｜演示此前已部署项目（4:15–5:25）

进入 GitHub 仓库 `https://github.com/ZhijianLuan-77/TTT-homework`。在浏览器展示**已经实际确认可访问的**部署域名，比如 Cloudflare Pages `https://ttt-homework.pages.dev/` 或 GitHub Pages `https://zhijianluan-77.github.io/TTT-homework/`，以现场实际结果为准。依次演示旧站点的任务清单、Markdown 笔记、倒计时和随机点名。屏幕中保留浏览器地址栏和平台实际域名。不要把 GitHub URL 当作部署域名。

## 第五幕｜收束与交付（5:25–6:00）

概括：“这次作品完成了前端界面、REST API、SQLite 关系数据层、账号数据隔离、自动化测试和部署配置，形成了可以运行和复现的全栈闭环。此前的网站也保持可访问。”
